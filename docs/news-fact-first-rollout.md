# Fact-First News Rollout

Owner-approved scope, November 11, 2026. This is not a new budget or model.

1. Verify a bounded starter set of existing official sources for model/technology
   news. Keep international reporting as discovery, not a substitute for missing
   official evidence in this starter route. Healthy quiet feeds are not errors.
2. Extract two to four complementary source-bound facts, validate literal quotes,
   event/model/market/numbers/conditions, and persist the immutable fact packet.
   The writer receives fixed paragraph-to-fact assignments, not an extraction job.
3. Write 50-120 words for short news, or 150-250 for sufficiently rich material.
   No mandatory advice, analysis, negative contrasts, filler or paid rewrites.
   Independently audit the final artifact against the facts AND source context.
4. Run offline positive/negative regressions, then fresh cases from two news
   types. One can be a separately owner-started production qualification case
   after a private success. Publish only that fresh production case after both
   types independently pass, then verify the existing distributor.
   Report real receipts, quality verdicts, costs and public URLs, not test counts
   as evidence of editorial success. If gates fail, quarantine and name the cause.

## Contracts

- Recipe: `news-fact-first-2026-11-v1`; historic v3 artifacts are unchanged.
- Three requests per candidate: facts, writer, independent audit. Full worst-case
  preflight and durable per-request reservations precede provider calls.
- USD0.50/UTC day, USD10/month and one publication/day remain shared. Production
  and private candidate counters include older recipes; no old URL retries.
- Private successes never publish. Production refreshes all source snapshots and
  rechecks exact provider outputs/receipts and all three publication gates.
- No schema migration, canonical-car mutation, DNS change or new credentials.
- Sources must remain accessible under the existing access/TDM rules. Official
  claims remain attributed claims, not independently measured specifications.
- Old word limits, trial authorizations, proofs, quarantines and unknown-use
  accounting are not rewritten to qualify for the new route.

## Release Evidence

Implementation and offline tests alone are not an operational release. The
scheduler changes only after two distinct, fresh, independently approved cases.
A production qualification run requires an explicit current-day owner command
and at least one real approved private case; it cannot publish before both types
pass. A new production article must pass its own exact three receipts,
source refresh, transaction, deployment and public HTML/sitemap verification.

## Short-Text Language Diagnostics

The new recipe treats the legacy seven-stopword heuristic as a diagnostic, not
proof that a 50-120-word text is not Swedish. The exact independent audit must
still approve Swedish quality; v3 retains its original language gate.

An operator-only remaining-review completion is prepared for a known false
language stop. Preparing it is NOT authorization. It requires separate owner
approval, an exact private parent and current UTC day, the same source hash,
unchanged text/facts, exact settled extraction/writer request hashes, and at most
one audit within USD0.10 and the ordinary allowance. It never buys writing,
changes the parent quarantine or publishes a private test. Counts and charges
remain; cross-record reporting must count shared prefix requests only once.

## Operational Continuity

The explicit official source set also includes existing BYD Germany, NIO,
Lexus Europe/UK, XPENG Switzerland, smart Europe and Electra adapters. This is
not an inferred-domain approval or permission to use Mobility statistics here.
Central facts must include required market context before prose is purchased;
the final headline/intro scope guard remains unchanged.

An already PASSED v4 qualification may survive an unrelated worker/registry edit
only through read-only revalidation of all three exact CURRENT provider request
hashes, raw responses, immutable facts/text/source bindings and current quality
gates. Never rewrite old records, reuse failed states or buy another audit just
for a registry edit. Production release still requires the current code identity
and fresh sources. A settled rejection must be reported as a rejection, not
hidden behind an empty-source outcome.
